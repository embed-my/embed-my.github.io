Embedding guide Privacy and security Troubleshooting

Is it safe to put on my page?

Yes, with the care you would give any embed. An iframe is a window onto another site, and the browser keeps what runs in it apart from your page. Here is what that means for this snippet, and where it stops.

  • The activity runs on Embed My's own address, not on your site. H5P packages contain JavaScript. Inside the frame it cannot read your site's cookies, logins or storage, or touch your page's content. The snippet grants the frame one permission, fullscreen: no camera, microphone or location.
  • One script runs on your page, and it is sixty lines. The iframe is only a window. The h5p-resizer.js line is the one piece of code the snippet runs on your page itself: it sets the frame's height when the frame reports it, nothing else, and you can read it. Leave it out and the frame keeps the minimum height.
  • No accounts, no cookies, no tracking, no learner records. The frame loads no analytics and reports to no one. Answers are not saved anywhere, so a reload starts the activity over. The browser caches the package's files and address so it loads faster next time; it keeps nothing about the learner.
  • Results go only where you say. On its own, the frame tells your page one thing: its height. xAPI statements are sent only if you name your page's origin in the developer options, and then to that origin alone.
  • Open source, both halves. The player is h5p-offline-player (MIT), the H5P runtime inside it is GPL-3.0, and this site is on GitHub. Anyone can read what runs.

What the frame cannot protect you from

  • A package you do not trust. Its scripts run inside the frame as they would on any H5P site: it can load outside content it names, such as a YouTube video or a web font, and send what it collects there anywhere. After a click inside the activity it could even send the visitor's whole tab to another address, which browsers allow any iframe. Embed only packages you would run as a script on your own site.
  • Packages embedded on the same site share the frame's storage there: one package's scripts can read another's files and address.
  • The package link is public in your page's HTML. Never use a secret or expiring link, and keep personal data out of the package.
  • The frame and the script come from Embed My. You trust this service as you trust any embed, which is why all of it is open source.

How long will my embed work?

For as long as this project is on GitHub. There is no expiry and nothing to renew, and the address in the snippet is one that cannot expire.

  • The snippet uses an address that cannot expire. It points at embed-my.github.io, which GitHub provides to this project for free, for as long as the project exists. Nothing to renew, and no one else can claim it. The embed-my.org you see in your browser is only a nicer name for this website; the snippet does not depend on it, so every embed already on a page would keep working if that name were ever lost.
  • Your package stays yours. The .h5p file lives on your host, not here. Embed My only points at it, so nothing of yours is lost if this project ends.
  • If the project ever stops, the frame shows an error. Your page itself keeps working: a frame that cannot load and a script that is not found break nothing around them. The activity is what goes missing.
  • You can run the same player yourself. The player is open source (MIT). Put it on your own site, or on any static host, and point the snippet at it. Nothing about your package has to change.

If you would rather load nothing from anyone

The iframe is only a window, but h5p-resizer.js runs on your page. Copy it to your own site and change the src in the snippet to your copy: it is sixty lines, MIT-licensed, and needs no updates. The frame is then the only thing your page takes from Embed My.

Questions people ask

Where do I get an .h5p file?

From wherever the activity was made. Lumi, H5P.com, h5p.org and the H5P plugins for Moodle, WordPress and Drupal all offer a download, usually under the activity's Reuse button.

Make sure the export includes its libraries. Exports from H5P.com and h5p.org often hold only the content and rely on the site they came from; such a file plays there but not anywhere else. Choose a complete export, then check it in the preview above. Packages and library files →

Can the file live on Google Drive, Dropbox or OneDrive?

Not through their ordinary share links. Those open a preview page rather than the file, and the file is not sent with the header a browser needs (CORS). Some of these services can give a direct link; test it in the preview, because many still lack the header.

The sure way is a host that gives the file a direct https://…/name.h5p address and allows cross-origin requests. GitHub Pages does both as it comes, and so does most web hosting where you can set a header. Preparing and hosting packages →

Does it work on WordPress, Moodle, Google Sites, Squarespace, Wix…?

On any page where you can paste HTML: look for the site's HTML, Embed, Custom HTML or iframe block. If the site keeps the iframe but removes the script, the activity still plays, at the minimum height you set above.

A site whose embed block takes only a web address, not HTML, can be given the frame's address alone: the src of the iframe in the snippet.

Why is the activity cut off, or followed by blank space?

The sizing script is missing, or your site removed it. Paste the snippet into a block that keeps scripts, or set the minimum height to the height the preview measures: it fills that field in for you once the activity has loaded. Troubleshooting →

Which browsers and devices does it work on?

Current Chrome, Edge, Firefox and Safari, on desktop and on phones. The page that holds the frame has to be served over https://.

The built-in browsers inside some social and messaging apps cannot run it. The frame then shows a link that opens the activity on its own page.

Can I see learners' scores or results?

Not here. Embed My keeps no accounts and no records, so treat an embed as an ungraded activity: visitors do it, and nothing is stored.

A developer can receive every xAPI statement on your own page as it happens, with the developer option above, and send it to a learning record store. Nothing is sent unless you ask for it that way. Results, xAPI and grades →

Can I update the activity after embedding it?

Yes. Replace the file at the same address and leave the snippet as it is. The player tells versions apart by the file's ETag or modification date, which nearly every host sends, so visitors get the new version on their next load.

Can I put several activities on one page?

Yes. Paste one snippet per activity. The script line only needs to be on the page once; extra copies do nothing.

Is it accessible?

The frame has a title that screen readers announce, the one you set above, and supports fullscreen. Inside it, keyboard and screen-reader behaviour come from the H5P content type and from how the activity was authored.

Before publishing, run through the activity with the keyboard alone, give video and audio captions or a transcript, and keep essential information available outside the activity too. Accessibility →

What does it cost?

Nothing. Embed My is free and open source, with no accounts, plans or limits of its own. The only thing you might pay for is wherever you host your package.

Something else? See the troubleshooting guide, or ask on GitHub.

embed-my Your content, anywhere

Embed My is a free, open-source project that puts interactive learning activities and documents on any website, without installing anything there. It is for teachers, instructional designers and anyone who runs a portfolio, school, course or department site, a blog or a CMS page that cannot take an H5P plugin.

Questions, ideas and bug reports are welcome on GitHub.
